## 1. 제품 개요

### 1.1 한 줄 소개

> **자정이 지나면 사무실의 모든 사물이 당신을 공격한다.** 마우스와 스테이플러로 야근을 버텨내고, 살아남은 만큼 수당을 챙겨가는 8분짜리 로그라이트.

### 1.2 비전

뱀서라이크는 "자동 공격 + 이동만 조작"이라는 초저진입 장벽 덕에 웹/모바일과 궁합이 좋지만, 대부분의 웹 클론은 ① 판타지 세계관의 반복, ② 후반부 카이팅 반복의 지루함, ③ 얕은 빌드 다양성에서 무너진다.

이 제품은 세 가지로 그 지점을 공략한다.

1. **친숙한 일상을 적으로 만든다.** 고딕 호러 대신 "야근"이라는, 타깃 유저 대부분이 몸으로 아는 소재. 스크린샷 한 장으로 설명이 끝나는 후크.
2. **빌드를 '진화'가 아니라 '합성'으로 만든다.** 슬롯을 소모하는 조합 시스템으로, 매 선택이 되돌릴 수 없는 트레이드오프가 된다.
3. **안전 플레이에 페널티를 준다.** 위험에 머물수록 보상이 오르는 '수당 게이지'로, 카이팅 무한 반복을 구조적으로 억제한다.

여기에 **8분이라는 런 길이**가 더해진다. 원작(20~30분)이 요구하는 시간 몰입은 모바일 웹에서 가장 큰 이탈 지점이다. 8분은 "출근길 지하철 한 구간", "점심 먹고 남는 시간"에 정확히 들어맞고, 한 판이 짧을수록 재도전 회전율이 올라 로그라이트의 성장 루프가 더 빨리 체감된다.

### 1.3 타깃 유저

| 세그먼트 | 설명 | 우선순위 |
|---|---|---|
| 1차 | 20~30대 직장인. 점심시간·퇴근길 짜투리 플레이. 뱀서류 경험 있음 | P0 |
| 2차 | 캐주얼 웹게임 유저. 설치 없이 링크 클릭 진입, 데일리 루프에 반응 | P0 |
| 3차 | 로그라이트 코어 유저. 빌드 최적화·엔드리스 랭킹 경쟁이 동기 | P1 |

| 지표 | 목표 | 비고 |
|---|---|---|

## 2. 컨셉 & 세계관

### 2.1 설정

도시의 밤 12시. 마지막 지하철이 끊긴 시각, 사무실에 남은 사람에게 "그것"이 온다.
쌓인 업무, 읽지 않은 메일, 끝나지 않는 회의가 물리적 실체를 얻어 몰려온다. 살아남는 방법은 하나뿐 — **아침 해가 뜰 때까지 버티는 것.**

톤은 진지한 호러가 아니라 **블랙코미디**다. 공포스러운 상황을 과장된 일상 사물로 표현해 웃기게 만든다. 이 톤이 SNS 공유와 스크린샷 밈의 연료가 된다.

### 2.2 시간 = 진행도

런의 경과 시간이 곧 게임 내 시각이다. HUD의 디지털 시계가 `00:00 → 06:00`으로 흐르고, 배경 팔레트가 심야의 청록 → 새벽의 보라 → 일출의 주황으로 램프된다. "얼마나 남았는지"를 별도 UI 없이 전달한다.

**표준 모드 8분 타임라인**

| 실경과 | 게임 시각 | 페이즈 | 설계 의도 |
|---|---|---|---|
| 0:00~1:00 | 00:00~00:45 | 도입 | 저밀도. 무기 1~2개 확보, 조작 학습 |
| 1:00~2:00 | 00:45~01:30 | 밀도 상승 | 첫 엘리트 1기. 보스 문법 예고 |
| 2:00~3:00 | 01:30~02:30 | 첫 합성 구간 | 특수 웨이브 1회. 재료 무기가 합성 가능 레벨 도달 |
| 3:00~4:00 | 02:30~03:30 | **미드보스** | 마감(스테이지1) / 회의(스테이지2). 수당 배수 최대 구간 |
| 4:00~5:30 | 03:30~04:30 | 고밀도 | 엘리트 2기. T2 합성 가능 |
| 5:30~6:30 | 04:30~05:15 | 특수 웨이브 | '정기 회의' — 사방 압박 |
| 6:30~8:00 | 05:15~06:00 | **최종 보스** | 부장님 3페이즈 → 일출 엔딩 |

### 2.3 모드 구성

| 모드 | 길이 | 목적 | 해금 |
|---|---|---|---|
| **정규 야근** (표준) | 8분 | 메인. 보스 2회, 완주 = 클리어 | 기본 |
| **칼퇴 러시** | 4분 | 짜투리 플레이·데일리 계약용. 보스 1회, 밀도 가속 | 기본 |
| **무한 야근** (엔드리스) | 무제한 | **랭킹 전용.** 8분 이후에도 난이도가 계속 상승, 생존 시간·점수 경쟁 | 10런 이후 |

> **왜 랭킹을 엔드리스로 분리하는가.** 표준 모드에 랭킹을 걸면 "완주"가 곧 만점이 되어 변별력이 없고, 모드별 랭킹을 이중 관리해야 한다. 랭킹을 엔드리스 단일로 두면 코어 유저의 경쟁 무대는 명확해지고, 캐주얼 유저는 8분 완주라는 별도의 성취를 갖는다.

## 3. 코어 게임플레이 루프

### 3.1 인게임 루프 (초 단위)

```
이동 → 적 자동 공격 → 경험치 젬 수집 → 레벨업 → 3택 중 선택
  ↓                                                    ↑
위험 구역 진입 → 수당 게이지 상승 → 보상 증가 ─────────┘
  ↓
피격 → 게이지 리셋 (긴장)
```

### 3.2 런 루프 (8분)

```
캐릭터/스테이지 선택 → 8분 생존 → 정산(수당 획득) → 광고 시청 시 2배
                                        ↓
                             메타 상점에서 영구 강화 → 다음 런 (즉시 재시작 버튼)
```

> 정산 화면에는 **"한 판 더" 버튼이 가장 크게** 놓인다. 8분 런의 가치는 회전율에 있고, 회전율은 재시작까지의 마찰에서 결정된다. 메뉴로 돌아가지 않고 같은 조건으로 바로 재시작 가능해야 한다.

### 3.3 데일리 루프

```
데일리 계약(3종) 확인 → 런 2~4회 → 계약 보상 수령
                              ↓
                    주간 엔드리스 랭킹 확인 → 시드 챌린지 도전
```

### 4.2 [시그니처 ①] 무기 합성 시스템

**문제 인식.** 원작 뱀서의 진화는 "무기 최대 레벨 + 지정 패시브 보유 → 자동 업그레이드"다. 정답이 하나로 정해져 있어 위키를 본 순간 빌드 탐색이 끝난다.

**해결.** 무기 슬롯 자체를 재료로 소비하는 **합성(Crafting)** 으로 바꾼다.

#### 규칙

- 무기 슬롯 **5칸**, 패시브 슬롯 **4칸**. *(8분 런에 맞춰 v0.1의 6/6에서 축소. 슬롯이 적을수록 합성 판단이 매 판 강제된다.)*
- 무기 2개(일부는 3개)를 재료로 합성하면 **재료가 슬롯에서 사라지고** 결과물 무기 1개가 들어온다.
  - 즉 합성은 **슬롯을 비우는 행위** → 새 무기를 넣을 여유가 생긴다.
  - 재료 무기의 레벨 투자는 일부 승계된다 (재료 평균 레벨의 50% 반올림).
- 합성 조건: 재료 무기 **각 레벨 3 이상**. *(8분 안에 T1 합성 2~3회, T2 1회가 가능하도록 v0.1보다 완화)*
- 조건이 충족되면 레벨업 3택 중 한 칸이 **합성 카드**로 대체되어 등장한다. (자동 진화 아님 — 플레이어가 선택)
- 합성 결과물은 재합성 가능. **T1 → T2** 2단계.

#### 합성 레시피 예시

| 재료 | 결과물 | 성능 |
|---|---|---|
| 스테이플러 + 형광펜 | **결재판** | 관통하며 지나간 적에게 '마킹', 마킹된 적 피해 +30% |
| 커피 + 전자레인지 | **에스프레소 폭탄** | 착탄 시 화상 장판, 화상 중 처치 시 연쇄 폭발 |
| 우산 + 정수기 | **비바람** | 회전 궤도 확대, 접촉한 적을 바깥으로 밀어냄 |
| 무선 마우스 + 무선 이어폰 | **드론 군집** | 유도 부메랑 3기, 처치 시 젬 자동 회수 |
| 명함 + 결재 도장 | **인사 발령** | 광역 산탄, 명중한 적 이동속도 -40% |
| 결재판 + 에스프레소 폭탄 (T2) | **월요일 아침** | 화면 전체 마킹 + 광역 폭발, 쿨다운 매우 김 |

> 런칭 목표: 기본 10종 → T1 합성 8종 → T2 합성 2종. 유효 빌드 아키타입 **5~6개** 확보.

#### 왜 이게 깊이를 만드는가

- 슬롯이 비므로 "합성할 것인가, 슬롯을 채운 채 넓게 갈 것인가"가 매 런의 판단이 된다.
- 재료 무기를 얼마나 키운 뒤 합성할지 = 타이밍 판단이 생긴다.
- 레시피는 **런 중 발견**(첫 합성 시 도감 해금)으로 탐색 동기를 준다.
- 8분 런이라 한 판에 모든 조합을 못 본다 → 반복 플레이 동기가 자연스럽게 붙는다.

### 4.3 적 & 웨이브 디렉터

- **스폰:** 화면 밖 링에서 스폰. 카메라 이동 방향 쪽에 가중치를 둬 "몰려오는" 느낌을 만든다.
- **디렉터:** 고정 웨이브 테이블 + 동적 보정. 플레이어의 초당 처치량을 측정해 스폰 밀도를 ±20% 범위에서 조정한다.
- **밀도 목표:** 동시 활성 적 **최대 800**(엔드리스 후반), 표준 모드 평시 200~400.
- **밀도 곡선:** 8분 압축에 맞춰 v0.1보다 가파르게. 1분 시점 30기 → 4분 250기 → 7분 500기.
- **특수 웨이브:** 성격이 명확한 웨이브를 90초마다 삽입 (예: "정기 회의" 사방 의자 압박, "택배 러시" 직선 돌진 다수).

### 4.4 [시그니처 ②] 보스 & 엘리트 패턴전

**문제 인식.** 뱀서라이크의 보스는 대개 "체력 많은 잡몹"이라 긴장감이 없다.

**해결.** 보스전 동안 **일시적으로 룰이 바뀐다.**

#### 엘리트 (런당 2회: 약 1:30, 4:30)

- 잡몹 스폰이 **일시 중단**되고 엘리트 1~2기만 남는다. 화면이 정리되어 패턴이 보인다.
- 각 엘리트는 명확한 텔레그래프(0.8초 예고)를 가진 공격 2종 보유.
- 처치 시 **보물 상자** — 무기 강화 또는 즉시 합성 기회.
- 소요 시간 목표: 20~30초.

#### 보스전

| 보스 | 등장 | 소요 | 기믹 |
|---|---|---|---|
| **마감** (스테이지1 미드) | 3:00 | ~50초 | 화면 가장자리에서 붉은 선이 좁혀온다. 활동 공간이 줄어든다. 본체를 때려야만 선이 후퇴한다. |
| **회의** (스테이지2 미드) | 3:00 | ~50초 | 원형 회의 장판에 갇힌다. 시계 방향 '발언권' 스포트라이트가 돌고, 안에 있으면 지속 피해. 회피 리듬 게임에 가깝다. |
| **부장님** (최종, 공통) | 6:30 | ~90초 | 3페이즈. ①서류 폭격(장판 회피) ②호통(원형 충격파, 엄폐물 뒤로) ③야근 지시(잡몹 대량 소환 + 본체 무적, 소환수 정리 강제) |

> 미드보스를 스테이지별로 다르게 두면 같은 8분 구조에서도 스테이지가 다르게 느껴진다. 콘텐츠 재사용 효율이 높은 구조다.

#### 설계 원칙

- 보스전 중 **수당 게이지가 배수로 상승** (§4.5) → 보스전이 곧 최대 벌이 구간.
- 시간 초과로도 통과 가능하되, 처치 시 보상 3배.
- 패턴은 **전부 회피 가능**해야 한다. 빌드가 약해도 실력으로 넘길 수 있게.

### 4.5 [시그니처 ③] 오버타임 게이지 — 신규 성장재화 수급

이 게임의 재화는 **수당(원)** 이다. 정산 화면에서 "오늘 번 돈"이 계산된다.

**문제 인식.** 뱀서라이크의 재화는 보통 "처치 수 × 계수"라 플레이 스타일과 무관하다. 안전하게 카이팅만 도는 게 항상 최적이 된다.

**해결.** **위험에 머무는 시간을 재화로 환산한다.**

```
게이지: 0 ──────────────────────── 100
배율:  1.0x                        3.0x
```

| 조건 | 게이지 변화 |
|---|---|
| 반경 150u 내 적 5기 이상 | +10 /초 |
| 반경 150u 내 적 15기 이상 | +20 /초 |
| 보스/엘리트 교전 중 | +15 /초 (중첩) |
| 주변 적 5기 미만 | -12 /초 (감소) |
| **피격** | **즉시 -35** |
| 체력 30% 이하에서 유지 | 획득 배율 추가 +0.5x |

- 게이지가 곧 **수당 배율(1.0x ~ 3.0x)** 이며, 획득 경험치 젬과 재화 모두에 실시간 곱연산된다.
- 8분 런 기준 최대 배율 도달까지 약 **6~7초**. 짧은 런에서도 게이지가 여러 번 오르내리도록 튜닝했다.
- HUD에 급여명세서 스타일 바. 최대 배율 도달 시 "특별 수당" 연출 + 사운드.
- 정산: `기본 수당 + Σ(구간별 배율 적용분) + 보스 처치 보너스 + 계약 달성 보너스`

#### 이 시스템이 만드는 것

- **적 무리 속으로 들어갈 이유**가 생긴다. "잡몹 벽을 뚫는 쾌감"이 보상과 직결된다.
- 방어형 빌드(우산, 정수기)와 화력형 빌드가 **다른 수익 곡선**을 그린다.
- 실력 있는 플레이어가 같은 8분에 3배를 번다 → 숙련 보상이 명확하다.
- 광고 2배와 곱해져 "잘한 판 × 광고" 조합이 강해진다 → 광고 시청 동기가 자연스럽다.

> **보류한 대안**
> - *운반 미션형*: 필드의 짐을 지정 지점까지 운반, 이동속도 저하. → 조작이 단순한 장르에서 스트레스 과다 우려.
> - *자발적 난이도 토글*: → 좋은 보조 시스템. **§4.7 메타에 '초과근무 서약'으로 편입**.

### 4.6 인게임 성장 (레벨업)

- 경험치 젬 수집 → 레벨업 → **3택** 제시 (리롤 1회, 밴 1회 — 메타로 확장)
- 카드 풀: 신규 무기 / 무기 레벨업 / 패시브 / **합성** / 즉시 효과(회복, 화면 정리)
- 레벨업 시 일시정지. 모바일에서는 카드가 하단에 크게 배치되어 엄지로 닿는다.
- **8분 런 예상 레벨: 28~36.** *(v0.1의 40~55에서 하향. 대신 레벨당 체감을 키워 선택 1회의 무게를 올린다.)*
- 초반 5레벨까지는 경험치 요구량을 매우 낮게 잡아, 첫 40초 안에 무기 2개를 손에 쥐게 한다.

### 4.7 메타 진행 (런 간 성장)

| 재화 | 획득 | 용도 |
|---|---|---|
| 수당 (원) | 런 정산 | 영구 업그레이드 구매 |
| 근속 포인트 | 실적/도전 과제 | 캐릭터·스테이지·모드 해금 |
| 도감 | 무기 합성 첫 발견 | 다음 런에서 해당 합성 카드 등장률 상승 |

**영구 업그레이드 (편의점 '만능 자판기')**

- 기본 스탯 강화 (체력/공격/쿨다운/픽업범위 등, 각 5단계)
- 시작 옵션 해금 (시작 무기 선택, 리롤 횟수 +1)
- **초과근무 서약** — 자발적 난이도 토글. 적 체력 +20%/스폰 +15% 등을 켤 때마다 수당 배수 +0.3x. 최대 5중첩. 엔드리스 랭킹 점수에도 반영.

**해금 흐름 (첫 1주일 설계)** — 8분 런이라 런 횟수 기준을 v0.1보다 촘촘하게 잡는다.

| 시점 | 해금 |
|---|---|
| 첫 런 종료 | 자판기(상점) 개방 |
| 2런 | 칼퇴 러시(4분) 모드 |
| 4런 | 캐릭터 2번째 (인턴) |
| 6런 | 스테이지 2 (편의점 골목) |
| 10런 | 무한 야근(엔드리스) + 랭킹 |
| 14런 | 초과근무 서약 |
| 18런 | 데일리 계약 |

### 4.8 데일리 계약

매일 3개 목표. 예: "수당 배율 2.5x를 30초 유지", "합성 무기 2개 완성", "마감을 40초 안에 처치".
보상은 수당 + 근속 포인트. 리텐션의 핵심 장치이므로 **광고 1회로 계약 1개 리롤** 가능.
계약 목표는 4분 모드로도 달성 가능하게 설계해, 시간 없는 날의 로그인 유지에 기여하게 한다.

## 6. 아트 디렉션 — 도트 픽셀아트

### 6.1 기본 규격

| 항목 | 사양 |
|---|---|
| 내부 렌더 해상도 | 가로 **480×270**, 세로 **270×480** (정수 배율 업스케일) |
| 업스케일 | `imageSmoothingEnabled = false`, 정수배(2x/3x/4x) 스냅 후 레터박스 |
| 캐릭터/잡몹 | **32×32** |
| 중형 적 | 48×48 |
| 보스 | 96×96 ~ 128×128 |
| 아이템/젬 | 16×16 |
| UI 아이콘 | 24×24 |
| 타일 | 32×32 |

> **정수 배율 스냅이 중요하다.** 픽셀아트를 비정수 배율로 늘리면 픽셀이 뭉개져 도트를 고른 의미가 사라진다. 카메라 위치도 픽셀 그리드에 스냅해야 스크롤 시 떨림이 없다.

### 6.2 팔레트

- **32색 고정 팔레트** 하나로 전 에셋 통일. (기존 공개 팔레트 채택 검토: Resurrect 32, Endesga 32 등)
- 시간대 램프: 심야 청록(`#1a2b3c`) → 새벽 보라(`#3d2b52`) → 일출 주황(`#e8875a`). 배경·조명 톤만 바뀌고 스프라이트는 셰이더 없이 팔레트 스왑으로 처리.
- **가독성 규칙 (타협 불가):**
  - 위험 요소(적 투사체, 예고 장판)는 팔레트의 **빨강 계열을 독점**한다. 배경·아군 이펙트에 빨강 금지.
  - 모든 적은 1px 어두운 외곽선. 배경과 실루엣이 분리되어야 한다.
  - 플레이어 캐릭터는 팔레트에서 가장 밝은 색을 갖는다. 적 500기 속에서도 자기 위치를 잃지 않게.

### 6.3 애니메이션 예산

| 대상 | 프레임 |
|---|---|
| 플레이어 | 대기 2, 이동 4, 피격 1, 사망 4 (좌우 플립으로 2방향 처리) |
| 잡몹 | 이동 4, 사망 3 (또는 파티클 대체) |
| 중형/원거리 | 이동 4, 공격 3, 사망 3 |
| 보스 | 대기 4, 패턴별 6~8, 사망 8 |
| 무기 이펙트 | 3~5 |

**런칭 총 물량 추정:** 스프라이트 약 **480~560 프레임** + 타일셋 2세트(각 40타일) + UI 아이콘 60개.

이 물량을 1인이 전부 손으로 그리는 것은 현실적이지 않다. 그래서 **AI 생성 → 도트 정리** 파이프라인을 채택한다(§6.4).
핵심은 **AI가 만드는 것과 손이 만드는 것을 분리**하는 데 있다. AI로는 정지 상태의 **베이스 스프라이트 60~70종**만 뽑고, 애니메이션 프레임·색 변형·방향 처리는 전부 Aseprite에서 파생시킨다. 전체 프레임의 80% 이상이 파생물이므로, 실제 AI 생성이 필요한 원본은 물량의 15% 수준으로 떨어진다.

### 6.4 제작 파이프라인 — AI 생성 → 도트 정리

**전제:** AI 이미지 생성은 *깨끗한 도트를 뽑아주지 못한다.* 픽셀 그리드가 어긋나고, 팔레트가 수백 색으로 흩어지고, 프레임 간 일관성이 없다. 따라서 AI는 **"실루엣과 컨셉을 빠르게 얻는 도구"** 로만 쓰고, 픽셀 확정은 사람이 한다. 이 경계를 흐리면 정리 비용이 직접 그리는 비용을 넘어선다.

#### 5단계 파이프라인

| 단계 | 작업 | 도구 | 산출물 |
|---|---|---|---|
| ① 생성 | 베이스 스프라이트 시안 생성 (정지 1포즈) | 이미지 생성 모델 | 512px PNG, 투명 배경 |
| ② 정규화 | 32×32(또는 48/96)로 **nearest-neighbor** 축소 → 32색 팔레트로 강제 양자화 | ImageMagick / Aseprite | 규격 준수 PNG |
| ③ 손보정 | 외곽선 1px 재작성, 실루엣 정리, 눈에 띄는 픽셀 노이즈 제거 | Aseprite | 확정 베이스 스프라이트 |
| ④ 파생 | 이동/피격/사망 프레임, 색 변형(적 티어 구분), 좌우 플립 | Aseprite | 전체 프레임 |
| ⑤ 빌드 | 아틀라스 + JSON 자동 추출 | Aseprite CLI | `public/atlas/*.png`, `*.json` |

②단계 양자화 예시:

```bash
magick input.png -filter Point -resize 32x32 \
  -dither None -remap palette32.png sprite.png
```

`-dither None`이 중요하다. 디더링이 켜져 있으면 32색 팔레트를 지켰더라도 픽셀 단위 노이즈가 생겨 도트 특유의 면 처리가 무너진다.

#### 생성 단계 규칙 (일관성 확보)

여러 캐릭터·적을 따로 생성하면 화풍이 제각각이 되어 게임이 짜깁기처럼 보인다. 다음을 **프롬프트 템플릿으로 고정**한다.

- **광원 방향**: 좌상단 고정. (다르면 ③단계에서 전부 다시 칠해야 한다)
- **시점**: 3/4 탑다운, 정면 약간 위. 스테이지 전체가 같은 시점이어야 한다.
- **팔레트**: 프롬프트에 팔레트 힌트를 넣되 신뢰하지 않고 ②단계에서 강제 remap.
- **비율**: 2~2.5등신 캐리커처. 32px에서 얼굴이 읽히는 최소 비율.
- **배경**: 완전 투명 또는 단색 마젠타(후처리로 제거).
- 같은 계열 적(예: 사무기기 3종)은 **한 번의 요청에서 함께 생성**한다. 개별 생성보다 화풍이 훨씬 잘 맞는다.

#### 검수 체크리스트 (③ 완료 기준)

- [ ] 32색 팔레트 이탈 색상 **0개** (스크립트로 자동 검사)
- [ ] 빨강 계열은 위험 요소에만 사용 (§6.2 규칙)
- [ ] 1px 외곽선이 실루엣 전체를 감싸는가
- [ ] 32×32 프레임 안에서 실루엣이 충분히 큰가 (여백 2px 이내)
- [ ] 배경 완전 투명, 반투명 픽셀 없음 (안티에일리어싱 잔재 제거)
- [ ] 축소했을 때(1x 표시) 무엇인지 알아볼 수 있는가 — **가장 중요**

> 검수 ①·②·⑤는 스크립트로 자동화한다. `/tools/validate-sprites.ts`가 팔레트 이탈·반투명 픽셀·규격 위반을 CI에서 잡아내면, 아트 품질이 개인의 집중력에 의존하지 않는다.

#### 라이선스 확인 (실서비스 전제이므로 필수)

수익화하는 서비스이므로 사용하는 생성 도구의 **상업적 이용 약관과 출력물 권리 귀속**을 착수 전에 확인해야 한다. 도구별로 상업 이용 조건·요금제별 권리·크레딧 표기 의무가 다르다. 이 확인 없이 500프레임을 만든 뒤 문제가 드러나면 전면 재작업이다. → §15 항목 L.

#### 빌드 통합

- `.aseprite` 원본 → CLI로 아틀라스 + JSON 자동 추출
- 빌드 스텝에서 아틀라스를 생성해 `public/atlas/`에 배치. 런타임은 아틀라스 1~2장만 로드.
- 스프라이트 좌표/피벗은 JSON으로 코드에 주입 — 아트 수정 시 코드 변경 없음.

## 7. 플랫폼 · 입력 · UX

### 7.1 입력

| 플랫폼 | 이동 | 보조 |
|---|---|---|
| PC | WASD / 방향키 | 마우스 조준(일부 무기), ESC 일시정지, Space 대시(해금 시) |
| 모바일 | 좌하단 가상 조이스틱 (터치 시작 지점에 동적 생성) | 우하단 대시 버튼, 상단 일시정지 |

- **자동 공격이 기본**이라 모바일에서도 손가락 하나로 완결된다. 이 장르를 고른 가장 큰 이유다.
- 모바일 **세로 모드가 기본**. 가로는 지원하되 UI 재배치.
- 세로에서는 카메라 줌아웃 폭을 조정해 위/아래 시야를 확보한다.

### 7.2 UX 원칙

1. **10초 안에 첫 적을 만난다.** 로딩 → 즉시 인게임. 첫 런은 캐릭터 선택도 건너뛴다.
2. **텍스트 튜토리얼 없음.** 첫 30초의 상황 맥락으로 학습시킨다.
3. **정산 화면이 하이라이트다.** 급여명세서 연출 — 항목별로 숫자가 올라가고 마지막에 총액. 여기가 광고·공유·재시작 버튼의 자리.
4. **재시작 마찰 0.** 정산에서 "한 판 더"가 가장 큰 버튼. 로딩 없이 즉시 재시작.
5. **한 손 조작 가능.** 모든 인게임 팝업 버튼은 화면 하단 40% 안에.

### 7.3 접근성

- 색맹 모드 (적/장판 팔레트 대체 — 32색 팔레트 구조라 스왑이 쉽다)
- 화면 흔들림 / 플래시 강도 조절
- 텍스트 크기 2단계
- 배경 밝기 조절 (심야 테마라 저조도 환경 대응 필요)

## 8. 수익화 — 무료 + 보상형 광고

**원칙: 진입장벽 0. 강제 광고(인터스티셜) 없음.** 모든 광고는 플레이어가 눌러서 보는 보상형이다.

| # | 위치 | 보상 | 제한 |
|---|---|---|---|
| 1 | 런 정산 | **수당 2배** | 런당 1회 |
| 2 | 사망 시 | **부활 1회** (체력 50% + 무적 3초 + 화면 정리) | 런당 1회, 하루 3회 |
| 3 | 데일리 계약 | **계약 1개 리롤** | 하루 2회 |
| 4 | 상점 | **데일리 무료 상자** | 하루 1회 |
| 5 | 레벨업 카드 | **추가 리롤** | 런당 1회 |

- 하루 광고 노출 상한 **8회**. 초과 시 버튼 비활성화 (경험 보호).
- ⚠️ **8분 런의 부작용 주의.** 런이 짧아 정산 화면이 자주 뜬다 → 광고 버튼도 자주 노출된다. 광고가 재시작 흐름을 끊지 않도록, 정산 화면에서 "한 판 더"는 광고와 **경쟁하지 않는 위치**에 두고, 광고 유도는 3런에 1회 정도만 강조 애니메이션을 준다.
- 광고 네트워크: 웹(특히 모바일 웹) 보상형 지원 여부 조사 필요 (§15 미결).
- **장기 옵션:** 광고 제거 + 코스메틱 팩 단발 결제. 게임플레이에 영향 주는 유료 아이템은 도입하지 않는다 (랭킹 신뢰성 보호).

## 9. 기술 아키텍처

### 9.1 스택

| 레이어 | 선택 | 근거 |
|---|---|---|
| 프레임워크 | Next.js (App Router) + TypeScript | 기존 스택 일치, 랜딩/랭킹 SSR 겸용 |
| 렌더링 | Canvas 2D (`OffscreenCanvas` 병용 검토) | 엔진 없이 직접 제어, 번들 최소 |
| 상태 | 게임 상태는 React 밖 (순수 TS 모듈). React는 메뉴/HUD 셸만 | 리렌더가 게임 루프에 개입하지 않게 |
| 패키지 | pnpm | 기존 |
| 테스트 | Vitest (시뮬레이션 단위 테스트 + 밸런스 시뮬) | 기존 |
| DB/ORM | Prisma + PostgreSQL | 기존 |
| 배포 | Vercel + 관리형 Postgres | |
| 아트 파이프라인 | AI 생성 → Aseprite 정리 → CLI 아틀라스 + JSON | §6.4 |

> ⚠️ **Canvas 2D의 한계 인지.** 동시 800 스프라이트 드로우콜은 2D 컨텍스트에서 저사양 모바일 기준 빠듯하다. §9.4 최적화를 전제로 진행하되, **M0 성능 프로토타입에서 목표 미달 시 PixiJS(WebGL) 전환을 결정한다.** 이를 위해 렌더러를 인터페이스로 분리한다.
> 다만 **도트 32px 스프라이트 + 아틀라스 1장**은 Canvas 2D에 유리한 조건이다. 텍스처 스왑이 없고 드로우 영역이 작아, 고해상도 벡터보다 훨씬 유리하다. 아트 스타일 선택이 기술 리스크를 실질적으로 낮췄다.

### 9.2 게임 루프

```
requestAnimationFrame
  └ accumulator 방식 고정 타임스텝 (60Hz 로직)
      ├ input.sample()
      ├ world.step(FIXED_DT)   ← 결정론적, 순수 함수적
      └ renderer.draw(alpha)    ← 보간 렌더, 가변 프레임
```

**핵심 원칙: 시뮬레이션은 결정론적이어야 한다.**

- 고정 타임스텝(1/60s), 부동소수 연산 순서 고정
- 모든 난수는 시드 기반 PRNG(xorshift128 등) 하나로 통일. **`Math.random()` 전면 금지 (ESLint 룰로 강제)**
- → 같은 시드 + 같은 입력 시퀀스 = 같은 결과
- → **§10.4 리플레이 기반 랭킹 검증의 전제**이자 버그 재현·자동 밸런스 시뮬의 기반
- 나중에 붙일 수 없는 종류의 결정이다. M1에서 못 박는다.

### 9.3 엔티티 구조

- **SoA(Structure of Arrays) 기반 경량 ECS.** `Float32Array`에 위치/속도/체력 병렬 저장.
- 종류별 고정 크기 **오브젝트 풀** (적 1024, 투사체 2048, 젬 4096). 런타임 할당 0 목표 → GC 스파이크 제거.
- **충돌:** 균일 공간 해시 그리드(셀 64u). 원-원 판정만. 프레임당 판정 예산 상한.
- **적↔적 분리:** 그리드 이웃 4셀만, 2프레임에 1회 갱신.

### 9.4 성능 예산

| 항목 | 목표 |
|---|---|
| PC (중급 노트북) | 60 FPS, 적 800 |
| 모바일 (중급 안드로이드) | 45+ FPS, 적 400 |
| 프레임당 로직 | ≤ 6ms |
| 프레임당 렌더 | ≤ 8ms |
| 초기 로드 | ≤ 1.5MB gzip, LCP ≤ 2.5s |
| 8분 런 힙 증가 | +15MB 이내 |

**최적화 전략**

- 아틀라스 1~2장, `drawImage` 배칭. 텍스트는 매 프레임 그리지 않고 캐싱.
- 내부 해상도가 480×270로 작으므로 픽셀 필레이트 부담이 낮다. 업스케일은 GPU가 처리.
- 화면 밖 엔티티 업데이트 스킵 (스폰 링 내부는 유지).
- 파티클은 별도 저해상도 레이어.
- 배경은 정적 타일 → 별도 캔버스에 1회 렌더 후 blit.
- 저사양 감지 시 자동 품질 강등 (파티클 수, 배경 디테일).

### 9.5 디렉터리 구조 (제안)

```
/app                  Next.js 라우트 (랜딩, /play, /rank, /me)
/game
  /core               루프, 타이머, RNG, 이벤트버스
  /ecs                컴포넌트 배열, 시스템
  /systems            movement, spawn, collision, weapon, pickup, director, overtime
  /content            무기/적/합성/스테이지/웨이브 데이터 (선언적 TS)
  /render             renderer 인터페이스 + canvas2d 구현 (+ 향후 webgl)
  /input              keyboard, touch-joystick
  /replay             입력 기록/재생, 검증
/components           React HUD·메뉴
/lib                  api client, auth
/prisma               스키마
/tools                스프라이트 정규화(remap/축소), 검수 스크립트, aseprite 아틀라스 빌드
/tests                결정론 테스트, 밸런스 시뮬
```

**콘텐츠는 전부 데이터로.** 무기·적·합성 레시피·웨이브를 코드가 아닌 선언적 데이터로 정의해, 밸런싱을 코드 수정 없이 하고 자동 밸런스 시뮬레이션(헤드리스로 1000판 돌리기)을 가능하게 한다. 1인 개발에서 이건 사치가 아니라 필수다.

## 10. 백엔드

### 10.1 범위

계정 · 서버 저장 · 랭킹 · 광고 보상 검증.

### 10.2 인증

- OAuth (Google) + 게스트 플레이.
- **게스트로 먼저 플레이하게 하고**, 첫 런 종료 후 "기록을 저장할까요?"로 계정 연결 유도. 진입장벽 0 원칙 유지.
- 게스트 진행도는 로컬에 두었다가 로그인 시 서버로 마이그레이션.

### 10.3 데이터 모델 (초안)

| 테이블 | 주요 필드 |
|---|---|
| `User` | id, provider, providerId, nickname, createdAt |
| `PlayerProfile` | userId, currency, careerPoints, unlocks(jsonb), upgrades(jsonb), version |
| `Run` | id, userId, mode, characterId, stageId, seed, durationMs, killCount, maxMultiplier, earned, oathLevel, result, createdAt |
| `RunReplay` | runId, inputLog(bytea, 압축), engineVersion |
| `Leaderboard` | period(weekly/all), mode(endless), userId, score, runId |
| `DailyContract` | userId, date, contracts(jsonb), progress(jsonb), claimed |
| `AdImpression` | userId, placement, rewardedAt, networkTxnId |

- **낙관적 동기화:** 클라이언트가 진행도를 로컬 유지, 런 종료 시 서버 반영. `version`으로 충돌 감지.
- 오프라인/네트워크 실패에도 플레이는 계속되고, 복구되면 큐가 전송된다.
- 8분 런이라 서버 쓰기가 잦다 → 런 종료 시 **1회 배치 전송**으로 묶는다.

### 10.4 랭킹과 치트 방지

**전제: 클라이언트는 신뢰할 수 없다.** 서버 랭킹을 걸면 반드시 조작 시도가 온다.

1. **1차 — 서버 상식 검증(전 런).** 런 길이 대비 처치 수, 획득 재화, 최대 배율, 레벨 곡선이 물리적 가능 범위인지 확인. 초과 시 랭킹 제외.
2. **2차 — 리플레이 검증(랭킹 상위권).** §9.2의 결정론 시뮬 덕에 클라이언트는 `(시드 + 프레임별 입력 + 선택 로그)`만 보낸다. 서버가 헤드리스로 같은 시뮬을 돌려 결과 일치를 확인한다. 상위 100위 + 무작위 표본에만 적용해 비용 통제.
   - 서버 시뮬은 같은 TS 코드를 Node에서 실행(코드 공유) → 이중 구현 불필요.
   - 입력 로그 크기: 60Hz × 8분 × 2바이트 ≈ 58KB, 압축 시 수 KB. 엔드리스는 상한을 두고 청크 전송.
   - `engineVersion` 불일치 시 해당 시즌 기록은 그 버전으로만 검증.
3. **3차 — 랭킹 구조로 완화.** 전체 순위 대신 **주간 시즌 + 시드 챌린지**(모두 같은 시드·조건)를 메인으로. 동일 조건이면 이상치 탐지가 쉽고 신규 유저도 매주 새로 시작한다.

**광고 보상 검증:** 광고 네트워크의 서버-투-서버(S2S) 콜백만 신뢰하고, 클라이언트의 "봤다" 주장으로는 지급하지 않는다.

### 10.5 API 개요

| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | `/api/run/start` | 시드 발급, 런 세션 생성 |
| POST | `/api/run/finish` | 결과 + 리플레이 제출, 검증 후 재화 지급 |
| GET | `/api/profile` | 진행도 조회 |
| POST | `/api/profile/upgrade` | 업그레이드 구매 (서버 권위) |
| GET | `/api/leaderboard?period&mode` | 랭킹 |
| GET/POST | `/api/contracts` | 데일리 계약 조회/수령 |
| POST | `/api/ads/callback` | 광고 S2S 콜백 |

> **시드를 서버가 발급**하는 점이 중요하다. 클라이언트가 시드를 고르면 "좋은 시드 뽑기" 조작이 가능해진다.

| **M1. 코어 루프 + 결정론** | 3주 | 이동·자동공격·젬·레벨업·8분 타이머, 시드 PRNG, 리플레이 기록 | 한 판이 끝까지 돌아감. 같은 시드+입력이 항상 같은 결과 (테스트로 보장) |
| **M2. 콘텐츠 1차** | 3주 | 무기 10 + 합성 10, 적 12종, 스테이지 1, **AI 파이프라인 구축 + 도트 에셋 1차** | 빌드 다양성 체감. 외부 플레이테스트 5명 |
| **M3. 시그니처 시스템** | 3주 | 오버타임 게이지, 엘리트 3종, 보스 3종 | 3대 차별점 전부 작동. 8분 페이싱 확정. **저사양 안드로이드 실기 성능 측정 완료 (M0 잔여 항목)** |
| **M4. 메타 & 백엔드** | 3주 | 계정, 저장, 상점, 영구 업그레이드, 해금 흐름 | 런 간 성장이 느껴짐. 8분 × 5런 세션이 지루하지 않음 |
| **M5. 모바일 & 폴리시** | 2.5주 | 터치 조작, 세로 UI, 4분 모드, 성능 튜닝, 사운드 | 실기(중급 안드로이드) 테스트 통과 |
| **M6. 랭킹·광고·출시** | 2주 | 엔드리스 모드, 리플레이 검증, 랭킹, 광고 연동, 계측 | 클로즈드 베타 → 출시 |

**합계 약 18주 (4개월 반).** 아트 작업은 별도 마일스톤이 아니라 M2~M5에 분산 병행한다.

**아트 일정 반영 (AI 생성 → 도트 정리 기준)**

| 구간 | 아트 작업 | 추가 소요 |
|---|---|---|
| M2 초반 | 파이프라인 구축 (프롬프트 템플릿 확정, remap/검수 스크립트, 아틀라스 빌드) | +0.5주 |
| M2~M3 | 베이스 스프라이트 60~70종 생성 + 손보정 | +1.5주 |
| M3~M4 | 애니메이션 파생, 보스 스프라이트 | +1주 |
| M5 | 타일셋 2세트, UI 아이콘, 이펙트 | +1주 |

**아트 순증 약 +3~4주 → 총 21~22주 (5개월).**
직접 제작(+4~6주) 대비 약 2주 단축이다. 절감 폭이 기대만큼 크지 않은 이유는, 시간을 잡아먹는 것이 *생성*이 아니라 *정규화와 손보정*이기 때문이다. AI의 실질 이득은 "속도"보다 **"백지에서 시작하지 않아도 된다"** 는 데 있다 — 1인 개발에서 실제로 사람을 멈추게 하는 건 그리는 시간이 아니라 무엇을 그릴지 정하는 시간이다.

**⚠️ 파이프라인 구축을 M2 초반에 반드시 끝낼 것.** 검수 스크립트 없이 에셋을 200장 만든 뒤 규격 미준수가 발견되면 전량 재작업이다. 파이프라인은 첫 에셋보다 먼저 만든다.

**단축 옵션:** 스테이지 2와 캐릭터 2를 런칭 후로 미루면 약 2주 단축 가능. 다만 런칭 시 콘텐츠 빈약이 리텐션에 직결되므로 권장하지 않는다.
