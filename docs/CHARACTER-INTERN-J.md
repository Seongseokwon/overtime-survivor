# 캐릭터 제안 및 적용 — 인턴 J

| 항목 | 내용 |
|---|---|
| 문서 상태 | 구현 완료, 플레이테스트 피드백 대기 |
| 대상 마일스톤 | M1 코어 루프의 첫 번째 플레이 가능 캐릭터 |
| 적용일 | 2026-08-21 |
| 구현 캐릭터 ID | `intern_j` |
| 시작 무기 | 형광펜 (`highlighter`) |

## 1. 캐릭터 콘셉트

**인턴 J**는 사무실의 규칙을 아직 완전히 배우지 못했지만, 움직임만큼은 누구보다 빠른 캐릭터다.
플레이어에게 “적을 정면으로 버티기보다, 이동 경로에 형광펜 장판을 남기며 공간을 관리한다”는
새로운 초반 플레이 패턴을 제공한다.

### 의도한 플레이 감각

- 이동으로 위험을 회피하고, 지나간 자리를 공격 구역으로 바꾼다.
- 높은 이동속도로 형광펜 장판을 이어 붙이기 쉽다.
- 낮은 체력 때문에 적과의 접촉이나 무리한 정지 플레이는 빠르게 위험해진다.
- 기존 사원 K의 수당 보너스와 겹치지 않는 “기동성/위험 관리” 축을 만든다.

## 2. 밸런스 제안

| 스탯 | 기본값 | 인턴 J | 의도 |
|---|---:|---:|---|
| 최대 체력 | 100 | 75 (-25%) | 실수 허용량을 줄여 이동을 강제 |
| 이동속도 | 2.0/frame | 2.4/frame (+20%) | 장판을 연결하고 포위망을 탈출 |
| 공격력 배수 | 1.0x | 1.0x | 장점이 화력으로 변질되지 않게 유지 |
| 수당 배수 | 1.0x | 1.0x | 사원 K와 경제적 역할을 분리 |
| 시작 무기 | 스테이플러 | 형광펜 | 이동 중심 플레이를 첫 프레임부터 설명 |

수치는 PRD의 캐릭터 초안에 있던 “이동속도 +20%, 최대 체력 -25%”를 그대로 반영했다.
다만 현재 게임에는 오버타임 게이지와 정산 시스템이 아직 없으므로, 수당 관련 보정은 넣지 않았다.

## 3. 적용 범위

### 콘텐츠

- `game/content/pack.ts`
  - `intern_j` 캐릭터 정의 추가
  - 시작 무기와 스탯 보정 데이터 선언
  - 데이터 변경에 맞춰 `contentVersion`을 4에서 5로 증가

### 시뮬레이션

- `game/ecs/world.ts`
  - `createWorld(seed, content, characterId?)` 지원
  - 캐릭터 보정값을 월드 생성 시 적용
  - `characterIndex`, `payMultiplier`를 월드/플레이어 상태에 저장
  - 알 수 없는 캐릭터 ID는 첫 번째 캐릭터로 대체

- `game/core/worldhash.ts`
  - 캐릭터 인덱스와 수당 배수를 월드 해시에 포함
  - 서로 다른 캐릭터 런이 동일한 해시 상태로 축약되지 않도록 함

### 플레이 화면

- `components/GameCanvas.tsx`
  - 현재 플레이 캐릭터를 `intern_j`로 지정
  - 캐릭터 데이터의 시작 무기(`highlighter`)를 자동 장착

- `components/Hud.tsx`
  - HUD 상단에 현재 캐릭터 이름 표시

- `game/render/atlas.ts`, `game/render/drawWorld.ts`
  - 인턴 J 전용 절차형 픽셀 프레임 추가
  - 실제 아트 에셋 교체 시 `FRAME_PLAYER_INTERN` 경계를 유지할 수 있도록 함

- `app/page.tsx`
  - 시작 화면에 인턴 J의 핵심 특징을 표시

## 4. 아트 상태와 교체 계획

현재 환경에서는 기본 제공 AI 이미지 생성 도구를 사용할 수 없었다. 따라서 이번 변경은
프로젝트가 이미 사용 중인 결정론적 절차형 32px 아틀라스에 인턴 J의 임시 스프라이트를 추가했다.

이 프레임은 최종 아트가 아니다. 실제 도트 에셋 파이프라인이 시작되면 다음 불변 조건을 지킨다.

1. `char/intern_j` 데이터 ID를 유지한다.
2. `FRAME_PLAYER_INTERN`을 최종 아틀라스의 인턴 J 프레임으로 매핑한다.
3. 캐릭터의 판정 반경과 중심점은 32px 플레이어 기준을 유지한다.
4. 형광펜의 노랑 포인트와 어두운 사무실 배경 대비를 유지한다.

## 5. 검토 요청 사항

다른 에이전트는 아래 항목을 중심으로 피드백하면 된다.

- 이동속도 2.4/frame이 실제 화면에서 너무 미끄럽거나 카메라 지터를 만드는가?
- 최대 체력 75가 형광펜 장판의 공간 제어력에 비해 지나치게 가혹한가?
- 시작 무기로 형광펜을 즉시 이해할 수 있는가?
- 인턴 J가 사원 K와 충분히 다른 선택으로 느껴지는가?
- 실제 도트 에셋으로 교체할 때 현재 임시 프레임의 실루엣이 도움이 되는가?

## 6. 검증 기준

- `tests/character.test.ts`에서 인턴 J의 체력·이동속도·수당 배수를 검증한다.
- 기존 결정론 테스트는 기본 캐릭터(`char_k`) 기본값으로 계속 통과해야 한다.
- `pnpm lint`, `pnpm test`, `pnpm build`가 통과해야 한다.
- 플레이 화면에서 `인턴 J · Lv.1`, 형광펜 시작 무기, 낮은 HP 바가 확인돼야 한다.

## 7. 롤백 방법

캐릭터 선택 UI가 추가되기 전까지는 `components/GameCanvas.tsx`의
`PLAYABLE_CHARACTER_ID`를 `char_k`로 바꾸면 기존 플레이 경험으로 돌아간다.
콘텐츠 정의와 월드 초기화 지원은 남겨도 기존 테스트와 기본 캐릭터 동작에는 영향을 주지 않는다.
